# Intercom MCP Conversation Exporter

Утилита выгружает обращения из Intercom через официальный удалённый MCP-сервер, очищает тексты и сохраняет результат в JSONL. Она не вызывает REST API Intercom напрямую.

## Требования

- Node.js 20 или новее.
- Доступ к Intercom workspace и токен с правами чтения обращений.
- US-hosted workspace: [Intercom MCP сейчас поддерживается только в US-регионе](https://developers.intercom.com/docs/guides/mcp).

Зависимости Node.js перечислены и зафиксированы в `package.json` и `package-lock.json`

## Установка

Из корня проекта установите зависимости и создайте локальный `.env`:

```powershell
npm ci
Copy-Item .env.example .env
```

Откройте `.env` и укажите `INTERCOM_ACCESS_TOKEN`. Не публикуйте этот файл и не вставляйте токен в командную строку или Git.

В Bash/macOS/Linux команды такие:

```bash
npm ci
cp .env.example .env
${EDITOR:-nano} .env
```

## Запуск

```bash
npm run export
```

Экспорт подключается к `https://mcp.intercom.com/mcp` с Bearer-токеном из `.env` и вызывает MCP-инструменты `search_conversations` и `get_conversation`: первый ищет обращения со страницами до 150 результатов, второй загружает доступную историю выбранного обращения.

Результаты создаются в `data/`:

- `data/conversations.jsonl` — одна запись на обращение, UTF-8.
- `data/manifest.json` — параметры и результат запуска: период, тип выборки, найденное и сохранённое количество, число страниц, ошибки, длительность, статус и ограничения.

`data/` исключена из Git, поскольку выгрузка содержит данные обращений. Скопируйте нужные файлы отдельно, если их требуется передать другому пользователю.

## Период и тип выборки

По умолчанию выбираются обращения за последние три календарных месяца по UTC. Начальная дата — та же календарная дата три месяца назад; если её нет в целевом месяце, используется последний день месяца. Конец периода — завтра, не включая этот день. Интервал имеет вид `[start, end)`.

Параметры задаются в `.env`:

```dotenv
START_DATE=2026-07-29
END_DATE=2026-10-30
EXPORT_TYPE=all
```

Обе даты необязательны. Формат дат — `YYYY-MM-DD`; `END_DATE` не включается в период. Если даты не указаны, применяется период по умолчанию.

`EXPORT_TYPE` принимает значения:

- `new` — обращения, созданные в периоде.
- `updated` — обращения, созданные до начала периода, но обновлённые в периоде по `updated_at`.
- `all` — объединение обоих наборов с дедупликацией по ID; значение по умолчанию.

`INTERCOM_API_VERSION` сохранён в `.env.example` для совместимости с локальной конфигурацией, но текущий экспортер его не использует: запросы выполняются через Intercom MCP.

## Формат данных

Каждая строка `conversations.jsonl` содержит только поля обращения и сообщения, доступные в ответе MCP:

```json
{
  "id": "123456789",
  "title": "Заголовок",
  "created_at": "2026-08-25T09:05:08.000Z",
  "updated_at": "2026-10-29T10:01:46.000Z",
  "messages": [
    { "role": "customer", "part_type": "source", "text": "Исходное сообщение" },
    { "role": "operator", "part_type": "comment", "text": "Ответ оператора" }
  ]
}
```

Времена нормализуются в ISO 8601 UTC с `Z`. Сообщения следуют в порядке, возвращённом MCP. Тип автора преобразуется так: `user` → `customer`, `admin` → `operator`, `bot` → `bot`; другие типы → `unknown`. Пустые после очистки сообщения пропускаются. Отсутствующие в MCP значения не подменяются выдуманными.

Перед записью удаляются распознаваемые email-адреса, URL, некоторые распространённые доменные зоны, форматированные телефонные номера, распознаваемые значения паролей/токенов и типовые подписи в конце письма. Остальной текст и имена сохраняются. Если MCP сообщает о недоступных страницах или неполной истории, manifest получает статус `partial` и описывает ограничения.

## Безопасность и Git

- `.env` содержит секрет и исключён из Git.
- `.env.example` содержит пустое значение токена и предназначен для коммита.
- `node_modules/` и `data/` исключены из Git.
- Перед коммитом проверьте `git status` и не добавляйте `.env` или файлы выгрузки.

## Структура проекта

```text
intercom_mcp/
├── .env.example       # Пример локальной конфигурации
├── .gitignore         # Исключает секреты, зависимости и данные выгрузки
├── export.js          # MCP-подключение, выборка, очистка и запись данных
├── package.json       # Команда запуска и зависимости
├── package-lock.json  # Зафиксированные версии npm-зависимостей
└── data/              # Создаётся при запуске; не коммитится
```
